# Biodata Exporter

Небольшое приложение для часов на Zepp OS. Забирает показатели с часов и отправляет их в Telegram или на свой HTTP endpoint. Куда отправлять, как часто и какие данные - настраивается в Zepp на телефоне.

## Что умеет

- Отправлять пульс, SpO₂, стресс, данные о сне, шаги, расстояние, калории, время жиросжигания, вставания, PAI, заряд батареи, статус ношения и информацию об устройстве.
- Работать в фоне с интервалом 1, 5, 10, 15, 30 или 60 минут.
- Пропускать отправку, когда часы сняты, если включить эту настройку.

Каждый показатель можно включить отдельно. Есть пресеты `Health`, `Activity`, `All` и `None`. По умолчанию включено всё, кроме информации об устройстве.

## Как запустить

1. Установить приложение на часы.
2. Открыть его настройки в Zepp на телефоне.
3. Выбрать `Telegram` или `Custom HTTP` и заполнить поля ниже.
4. Выбрать показатели и интервал, проверить, что `Enabled` включён.
5. На часах нажать `Start export` и выдать разрешения на фоновую работу и расписание.

Остановить отправку можно кнопкой `Stop export` на часах. Переключатель `Enabled` в настройках ставит экспорт на паузу, само расписание при этом остаётся.

### Telegram

Нужны токен бота и ID чата. Ввести их в `Bot token` и `Chat ID`. У бота должен быть доступ к чату; для личных сообщений сначала открыть с ним диалог.

Сообщение приходит с заголовком `Biodata Exporter` и выбранными показателями в JSON.

### Свой сервер

Выбрать `Custom HTTP` и указать адрес в `Endpoint URL`. Приложение отправит `POST` с заголовком `Content-Type: application/json`.

Адрес задаётся в настройках Zepp - менять код и пересобирать приложение при смене сервера не нужно.

## Как выглядят отправляемые данные

### Запрос на свой сервер

Пример тела HTTP-запроса со всеми 13 показателями, включая `Device info`. Для такого набора нужно выбрать пресет `All` в настройках. Значения условные:

```json
{
  "app": "Biodata Exporter",
  "metrics": {
    "recordTime": 1793318400,
    "heartRateLast": 72,
    "battery": 85,
    "calorie": 247,
    "bloodOxygen": {
      "value": 98,
      "time": 1793318100,
      "retCode": 2
    },
    "distance": 3391,
    "fatBurning": 39,
    "pai": {
      "total": 155,
      "today": 2
    },
    "sleepInfo": {
      "score": 93,
      "deepTime": 103,
      "startTime": 1380,
      "endTime": 1830,
      "totalTime": 450
    },
    "stands": 5,
    "steps": 4200,
    "stress": {
      "value": 49,
      "time": 1793318100
    },
    "isWearing": 1,
    "device": {
      "width": 480,
      "height": 480,
      "screenShape": 1,
      "deviceName": 123,
      "keyNumber": 2,
      "deviceSource": 123456,
      "keyType": "normal_21",
      "deviceColor": 3,
      "uuid": "00000000000000000000000000000000"
    }
  }
}
```

`recordTime` - время сбора в Unix-секундах, передаётся всегда. Остальные поля зависят от выбранных показателей и того, что удалось прочитать с часов. Отдельного поля для токена авторизации или своих HTTP-заголовков пока нет.

Состав `device` зависит от модели и версии Zepp OS: приложение передаёт объект, который возвращает система. Поле `uuid` доступно начиная с API 4.2; на более ранних версиях его не будет. [Описание полей устройства](https://docs.zepp.com/docs/reference/device-app-api/newAPI/device/getDeviceInfo/).

### Что означают поля

| Поле | Что внутри |
| --- | --- |
| `recordTime` | Время сбора показателей, Unix-секунды. |
| `heartRateLast` | Последний доступный пульс, уд/мин. |
| `battery` | Заряд батареи, %. |
| `calorie` | Калории, ккал. |
| `bloodOxygen` | SpO₂: `value` - %, `time` - время измерения, `retCode` - код результата (`2` - успех). |
| `distance` | Пройденное расстояние, метры. |
| `fatBurning` | Время жиросжигания, минуты. |
| `pai` | `total` - общий PAI, `today` - PAI за сегодня. |
| `sleepInfo` | `score` - оценка сна, `deepTime` - глубокий сон, `totalTime` - общая длительность сна. Длительности в минутах; `startTime` и `endTime` - минуты от 00:00, могут превышать 1440 при переходе через полночь. |
| `stands` | Количество вставаний. |
| `steps` | Количество шагов. |
| `stress` | `value` - показатель стресса, `time` - время измерения. |
| `isWearing` | Числовой статус: `0` - часы сняты, `1` - надеты, `2` - движение, `3` - не определено. |
| `device` | Объект с информацией об устройстве из Zepp OS. Добавляется, если включить `Device info`. |

## Что учитывать

Интернет-запросы идут через телефон. Нужны Bluetooth-соединение с часами и интернет на телефоне. Без связи текущий запуск пропускается; очереди для отправки накопленных данных нет.

Приложение читает доступные значения датчиков. Оно не запускает новое измерение пульса или SpO₂ и не выгружает историю за несколько дней. Если какой-то показатель не удалось прочитать, он пропускается.

Фоновый сервис вызывается раз в минуту, а выбранный интервал проверяется на телефоне по времени последней успешной отправки. Это не гарантия доставки секунда в секунду.

В разделе `Status` видны последняя отправка, HTTP-статус и ошибка. `Next run` сбрасывает ожидание интервала для следующего запуска сервиса. `Clear` очищает статус и время последней отправки - после этого следующий запуск тоже сможет отправить данные сразу.

## Как собрать и установить приложение на часы

Проект использует Zepp OS API 3.0 и ZML. В `app.json` настроены круглый экран шириной 480 и прямоугольный шириной 390. Работу на конкретной модели нужно проверять отдельно.

### Шаг 1 - Подготовить часы и телефон

Подключить часы к приложению Zepp на телефоне. Часы должны поддерживать Zepp OS API 3.0 и фоновый сервис, который использует приложение.

### Шаг 2 - Установить инструменты на компьютер

- Установить [Node.js LTS](https://nodejs.org/) на компьютер. npm устанавливается вместе с ним.
- Установить [Zeus CLI](https://docs.zepp.com/docs/v2/guides/tools/cli/) - инструмент для сборки приложений Zepp OS. Команда установки ниже.
- Установить Zepp на телефон для загрузки приложения на часы.

После установки Node.js открыть новый терминал. На Windows подойдёт PowerShell. Проверить, что Node.js и npm доступны:

```sh
node -v
npm -v
```

Установить Zeus CLI и проверить его версию:

```sh
npm install -g @zeppos/zeus-cli
zeus -v
```

### Шаг 3 - Скачать исходники и установить зависимости

Скачать исходники репозитория через `Code → Download ZIP` на GitHub и распаковать архив или клонировать репозиторий через Git.

Открыть терминал в папке проекта - там, где лежат `package.json` и `app.json`. Установить зависимости:

```sh
npm install
```

ZML и типы Zepp OS установятся автоматически из `package.json`. Следующие команды тоже выполнять из этой папки.

### Шаг 4 - Включить режим разработчика в Zepp

На телефоне открыть `Zepp → Профиль → Настройки → О приложении` и нажать на значок Zepp 7 раз подряд, пока не появится сообщение о включении режима разработчика.

Вернуться в профиль и открыть страницу подключённых часов. Там будет доступен режим разработчика со сканированием QR-кода. Названия пунктов могут отличаться в зависимости от языка и версии Zepp. [Инструкция Zepp](https://docs.zepp.com/docs/guides/tools/zepp-app/).

### Шаг 5 - Собрать приложение

Для получения установочного пакета выполнить:

```sh
zeus build
```

Если Zeus предложит выбрать устройство, выбрать вариант для подключённых часов. Готовый пакет появится в `dist/`.

Для установки через телефон выполнить:

```sh
zeus login
zeus preview
```

`zeus login` откроет вход в аккаунт платформы разработчиков Zepp. `zeus preview` сам соберёт приложение и покажет QR-код - отдельно запускать `zeus build` перед ним необязательно. Если появится запрос на выбор устройства, выбрать подключённые часы.

### Шаг 6 - Установить приложение по QR-коду

На телефоне открыть `Zepp → Профиль → Подключённые часы → Режим разработчика → Сканирование`. Отсканировать QR-код из терминала и дождаться установки. Приложение появится в списке приложений на часах.

### Шаг 7 - Настроить отправку

В настройках Biodata Exporter в Zepp выбрать Telegram или свой HTTP endpoint, заполнить поля назначения и выбрать показатели. Затем открыть приложение на часах и нажать `Start export`.

Результат отправки можно проверить в разделе `Status` в настройках. Подробности команд сборки - в [документации Zeus CLI](https://docs.zepp.com/docs/v2/guides/tools/cli/).

## Что где лежит

- `page/` - экран часов и кнопки запуска/остановки.
- `app-service/` - фоновый сбор показателей.
- `app-side/` - проверка настроек и отправка через телефон.
- `setting/` - настройки в Zepp.
- `utils/settings.js` - общие ключи, значения по умолчанию и список показателей.
- `assets/` - иконки приложения.
